0.12.0 makes one of the proxy's connection caps a setting. hoster lets one client address hold
at most 256 open connections, so one client cannot take every slot. That limit can now be
raised, for example for an event where everyone in the room comes through the same network
address.

Nothing needs editing to update. See [Updating](#updating).

# Connections per address

The new key `proxy.connections_per_address` sets how many connections one client IPv4 address
or IPv6 /64 may have open at once. A connection beyond it is refused when it is accepted, and
the refusal is counted on the System page. The default stays 256.

```toml
[proxy]
connections_per_address = 2048
```

The environment variable `HOSTER_PROXY__CONNECTIONS_PER_ADDRESS` sets it too. It must be at
least 1. hoster reads it at startup, so restart hoster after changing it. **Settings** shows the
value in force under *Reverse proxy*.

The total cap still applies: hoster refuses new clients while it has 4096 file descriptors open.
That limit is not configurable, so above about 4000 connections one address reaches it before
its own cap.

# Updating

```sh
hoster update
```

Or use *Update* on the System page. `hoster.toml` needs no edits, since the new key has a
default. The systemd unit, the log store and the deploy actions are unchanged. There is no need
to run the install script again, and stacks don't need redeploying.

Rolling back to 0.11.0 is safe as long as `hoster.toml` does not set `connections_per_address`.
0.11.0 rejects keys it doesn't know, so remove it first. See
[[install#updates-and-rollback|Updates and rollback]].
